Provider-executed tool calls (`--provider-tool`) are now counted and bounded at the loop level: the loop counts `tool-call` stream parts flagged `providerExecuted` into the `toolLimits` counters, and once the observed run total exceeds `maxToolCalls` the run stops (with `aborted: true` and an error event) instead of letting server-side fan-out continue unbounded. `onPostToolUse` now fires for provider-executed results — with a new `providerExecuted: true` marker and `durationMs: 0` — and `tool-call`/`tool-result` progress events carry `providerExecuted: true`. Provider results reach the event stream as a bounded descriptor (tool name + payload size); the payload itself only appears behind `emitFullResult: true` or in the hook's ToolResult, so operator logs and telemetry no longer see it by default. Provider-side tool errors surface as bounded `tool-result` events (`PROVIDER ERROR`, error text clipped at 200 chars) instead of being silently dropped. `onPreToolUse` is deliberately not fired for provider-executed calls because its deny/stop decisions cannot be enforced after server-side execution. Pure-local runs keep their existing per-call denial semantics.
